# OS hardening and base configuration

## Общая информация

Операционная система: **Ubuntu Server LTS**  
Назначение сервера: **Infrastructure host (IaC / core-infra)**  
Среда: **локальная сеть (LAN)**  
Тип доступа: **SSH**

Данный документ описывает **базовые настройки операционной системы**,
которые выполняются **вне Infrastructure as Code** и считаются частью
начальной инициализации сервера.

Эти настройки:
- выполняются один раз при подготовке сервера;
- не управляются через Docker или IaC;
- фиксируются в документации как архитектурные договорённости.

---

## Принципы

- Сервер не используется для разработки.
- Все изменения инфраструктуры выполняются **после bootstrap** и **через IaC**.
- Настройки ОС минимальны и направлены на безопасность и предсказуемость.
- Повторный запуск bootstrap на рабочем сервере **не допускается**.

---

## Timezone

На сервере установлен единый timezone для корректной работы логов,
планировщиков задач и отладки.

### Текущий timezone

Проверка текущего значения:
```bash
timedatectl
```

Ожидаемое значение:
```bash
Time zone: Asia/Bishkek
```

## Управление

Timezone устанавливается вручную на уровне ОС.

Управление timezone через IaC не используется.

Изменение timezone допускается только при полном пересоздании сервера.

SSH configuration
Общие правила доступа

Доступ к серверу осуществляется только по SSH.

Используется аутентификация по SSH-ключам.

Парольная аутентификация запрещена.

Вход под пользователем root запрещён.

Каждый пользователь использует личный SSH-ключ.

Проверка текущих параметров SSH

Для проверки фактической конфигурации SSH используется команда:

sudo sshd -T | grep -E 'permitrootlogin|passwordauthentication'


Ожидаемые значения:

permitrootlogin no
passwordauthentication no

Управление SSH-доступом

Добавление пользователей осуществляется через создание системных пользователей.

SSH-ключи добавляются в ~/.ssh/authorized_keys.

Перед изменением SSH-настроек необходимо иметь активную SSH-сессию,
чтобы избежать потери доступа.

Firewall (UFW)

На сервере используется UFW (Uncomplicated Firewall) с минимальной конфигурацией.

Принципы

По умолчанию запрещены все входящие подключения.

Разрешается только SSH-доступ.

Все остальные порты открываются исключительно через core-infra
(reverse proxy, Docker).

Разрешённые подключения

SSH (OpenSSH)

Проверка статуса firewall
sudo ufw status


Ожидаемый результат:

Status: active

To        Action  From
OpenSSH  ALLOW   Anywhere

Docker access policy (OS level)

Docker установлен на уровне ОС.

Работа с Docker осуществляется без sudo.

Доступ к Docker имеют только пользователи,
входящие в группу docker.

Проверка доступа
groups


В списке групп должен присутствовать:

docker
